## Execution sequence

### 1. Reproduce and establish trustworthy previews

Create a baseline contact sheet for every active family, theme, and motion mode.
Use external SVGs through `<img>` as the primary presentation, matching GitHub.
Keep a separate inspectable SVG view for geometry diagnostics.

Fix the preview first: retain actual `<picture>` markup in acceptance mode; keep
manual theme/variant controls in an explicitly labeled gallery. Measure both
viewport width and image width. Record `currentSrc`, loaded dimensions, and image
load failures. Include the legacy families and all icons in the gallery.

Assign a stable defect ID, source element, theme, width, animation time, screenshot,
and expected behavior to each reproduced bleed. Concentrate first on the mobile
header focus grid, wizard spell/quote boundary, metric rings/captions, atlas labels,
and delivery return connector.

### 2. Repair geometry and typography at the source

- Give text blocks explicit rectangles and padding. Measure real rendered glyph
  extents with the intended font and its fallback; transform local bounds into
  the parent coordinate system. Exclude definitions, hidden groups, and intended
  shadow duplicates from naive overlap tests. Account separately for strokes,
  markers, filters, and animation travel.
- Separate stationary placement transforms from animated transforms using nested
  groups where necessary. Reserve a complete motion region for the wizard and
  keep its spell and glow clear of the quote at every phase.
- Route connectors through empty space behind panels. Leave roughly 8 CSS px
  between decoration and readable text and 12–16 CSS px at outer content edges.
  Use explicit `fill="none"`, suitable line joins/caps, and locally scoped clips
  where those address a reproduced failure.
- Clip decoration to its intended region, but fix copy/layout instead of clipping
  away overflowing letters. Avoid applying `overflow:hidden` indiscriminately.
- Reduce offset duplicate lettering, heavy text shadows, and overlays if they
  cause visible ghosting at actual display size. Keep grain away from small type.
- Validate theme variants from shared source values rather than fixing just dark
  desktop output. Namespace embedded IDs and CSS when composing multiple marks.

### 3. Polish each family

| Surface | Intended result |
| --- | --- |
| Masthead | A strong name and concise role line; purposeful use of the full width; a compact focus summary. On mobile, wrap the role and simplify or stack focus items. Move secondary explanation into existing README prose when needed. |
| Wizard | A recognizable pixel-art signature with a clearly separated, readable two-line quote. Give mobile its own taller composition if needed. Keep Layla readable or place that note in normal text rather than shrinking it. |
| Impact | Large values with plainly readable labels; replace decorative certification language with “Selected delivery impact.” Keep the supplied figures unchanged and avoid implying all four figures are independently audited. Use a two-by-two layout only where it stays readable; stack at the narrowest size if needed. |
| Atlas | Preserve the central layered artifact and ten-product grouping. Reduce footer microcopy and tracking; make group labels and product names legible. Keep the conceptual-map qualification. |
| Delivery loop | Four clear steps, aligned nodes, and a return path in its own lane. Make the return caption readable without squeezing it against the frame. |
| App icons | Consistent optical size and padding at the actual 40px display size. Preserve identity and provenance; adjust wrappers rather than redesigning product logos. Static icons must show a complete, recognizable pose. |

Typography targets apply to **rendered CSS pixels**, not SVG units: aim for at
least 14px for meaningful secondary copy, 16px for primary labels, and 12px for
nonessential metadata. If these do not fit, simplify or move text into the README.
For example, at an actual 288px image width, a 720-unit canvas needs 35-unit type
to render at 14px. Changing only the canvas number does not improve readability.

Use a small consistent type hierarchy, calmer letter spacing, matched margins,
and harmonized border/line weights. Preserve contrast in both themes. Avoid new
claims, extra badges, decorative statistics, or additional content sections.

### 4. Make motion coherent and still states complete

Keep readable text stationary after a short entrance. Let the wizard provide the
main ongoing personality; make diagrams settle and reduce competing motion in
other families. Verify every icon's static pose rather than assuming removing
animation tags preserves a useful result.

Provide a genuinely still path for every active animated family. Existing internal
reduced-motion CSS can remain when proven in image context; add explicit static
siblings if needed for consistent fallback selection. The gallery's still
control must actually stop CSS and SMIL motion. An animation-disabled frame must
never leave key content transparent or absent.

### 5. Validate, document, and prepare the review

Use a small reproducible validator and browser fixture rather than a large testing
framework. Structural checks should cover XML parsing, per-document unique IDs,
fragment references, README asset existence, intended variant completeness,
accessible titles/descriptions, and no newly introduced scripts or remote assets.
Embedded fonts are not remote assets. Run generators twice and confirm identical
bytes; regenerate manifests with the outputs.

Rendering matrix:

- Both light and dark themes; regular and reduced motion.
- Viewports 320, 375, 390, 600, 601, 700, 701, 768, 1024, and 1440px to exercise
  current breakpoint boundaries and the actual README column. Retest either side
  of any revised breakpoint. Include a 288px image column and representative
  640/800/900px columns; a viewport width is not an image width.
- One complete cycle per animation plus delay offsets; capture named keyframes
  and midpoints, especially maximum stroke/particle travel. For a 6.4-second
  wizard cycle, include casting and recovery, not just the opening frame.
- Intended embedded fonts and fallback fonts, plus 200% browser zoom. Check all
  meaningful text, image loading, section anchors, and table behavior.
- Start browser automation with Obscura; use Safari if unavailable or unsuitable.
  Require real Safari visual acceptance. Engine emulation or a forced gallery is
  not proof of Safari or native `<picture>` behavior.

Pass criteria: no unintended text collisions, cropped glyphs, line crossings
through text, or escaping effects in sampled states; readable primary content at
the smallest width; correct loaded variant; complete still frames; no broken
references; deterministic generation. Automated bounds checks flag candidates;
visual review determines whether intentional illustration overlaps are valid.

Update `DESIGN.md` and validation evidence to describe the final assets and exact
tested matrix. Replace stale “preserved original assets” claims. Save before/after
comparisons and a concise defect-to-fix summary. A later authorized publication
must be followed by a live GitHub profile check; local rendering is not that proof.
If a Graphify graph exists by execution/publication time, follow the repository's
incremental-update and scoped-query requirements.
